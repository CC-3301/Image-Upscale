## 缘起（2026-09-20，v0.2.9 发布后登记）

工单 51 的 r1 修复轮修掉了 `LastAddSuffix` 的同类缺陷（记忆值被 `OnClosing` 抹掉）时，实施者
顺带发现 `LastDownFilter` 有**完全同形**的问题，已实测复现。当时按「越界发现记入批次末尾」处理，
未在本票外动手。

## 现象（实测）

`setting.ini` 里 `LastDownFilter=box`，当次启动时 **models 目录读不出来**（缺失/清单解析失败），
优雅关闭 GUI 后 `LastDownFilter` 被**改写为 `lanczos`** —— 用户的降采样方式选择被静默重置。

## 根源

- `gui/MainWindow.xaml.cs` 的 `RestoreSettings` 在 `_models.Count == 0 || ModelBox.SelectedIndex < 0`
  时提前 return，跳过按 `setting.ini` 恢复下拉选中项。
- 构造函数里 `DownFilterBox.SelectedIndex = 0`（= Lanczos）是唯一的初始状态。
- `OnClosing` **无条件**写 `s.DownFilter = SettingsStore.DownFilterTokenAt(DownFilterBox.SelectedIndex)`
  → 把初始值当作用户选择写回。
- 与工单 51 修掉的 `_addSuffix` 缺陷同形（那次的红→绿证据：`LastAddSuffix` 1→0）。

## 方案要点（与工单 51 fix ② 同形，约 5 行）

- 在构造函数里复用已有的 `SettingsStore.Load()` 结果，**先**把 `DownFilterBox.SelectedIndex`
  设成 ini 记录值（非法/缺键回退第 0 项），**再**做需要模型信息的恢复 → 该字段与「模型是否加载成功」
  解耦，`OnClosing` 写回的一直是权威值。
- 或（等价思路）让 `OnClosing` 仅在「成功恢复过设置」或「用户真实改动过」时写该键。任选一种，别两套都做。

- [x] 引擎缺失以外的场景（清单为空、模型未选中）同样不改写用户值

## 未决 / 风险

- 触发条件为异常路径（models 缺失），用户面影响是"设置被重置"，非数据丢失。
- 同类缺陷可能还有第三处（`FormatBox` / `QualityInput` / 模式三选一是否也走 `RestoreSettings`）——
  动手时一并 grep `OnClosing` 里的所有 `s.* =`，确认是否都需要同样的解耦。
