# 43: 目标尺寸模式改为多轮原生超分（放大不用插值，对齐 waifu2x）

## 起因（维护者 2026-09-18）

工单 42 讨论降采样滤镜时发现：目标倍率超过模型原生最大倍率时（如 2x 模型要 3 倍），最后一步是**插值放大**。维护者要求「放大行为要和 waifu2x 一致，放大时不要用插值算法」。

## waifu2x-caffe 的行为（`common/stImage.cpp` + `common/waifu2x.cpp`）

```cpp
const int scaleNum = ceil(log(nowFactor.toDouble()) / log(ScaleBase));  // ScaleBase = 2
for (int i = 0; i < scaleNum; i++) ReconstructScale(...);              // 循环跑 2x 模型
// 收尾 Postprocess → ShrinkImage(...)  → INTER_CUBIC（<0.5 倍时 INTER_AREA）
```

- 放大**全部由模型完成**（2x 循环直到超过目标），收尾**永远是缩小**，所以它不需要"放大滤镜"。
- 唯一朝放大方向的插值是喂模型**之前**的预放大，用 `INTER_NEAREST`（`GetScalePaddingedImage`），模型负责修回来。
- alpha 也过同一个网络（`GetScalePaddingedA` → `ReconstructByNet`）；其 release note 明确：这样修掉了透明边缘发糊，代价是带 alpha 的图约 2 倍耗时。

## 变更

1. **`plan_native_scales()`（新增）**：目标尺寸模式的原生档计划 —— 在"轮数最少"的方案里取"累积倍率最小"的档位组合：
   - 存在单档 ≥ 目标倍率 → 就用那一档（与旧行为一致、收尾缩放最温和）；
   - 目标超过模型最大原生档 → 逐轮叠加（2x 模型要 3 倍 → `[2,2]` = 4x；2/3/4 档要 5 倍 → `[4,2]` = 8x）。
   - 计划保证累积尺寸 ≥ 目标，**收尾 resize 永远是缩小**。
2. **`run_chain()`（新增，run_files 内的 lambda）**：按 plan 逐轮跑模型，每轮确保权重/档位与当轮原生档匹配；轮间不插值。RGB 与 alpha 共用同一条链。
3. **alpha 也过模型**：把 alpha 复制成 3 通道喂同一条链，取第 0 通道后按同一条降采样规则缩到输出尺寸 —— 去掉原来的"alpha 插值放大"（那正是 waifu2x 修掉边缘发糊的做法）。
4. `pick_native_scale()`（单档选择）被 `plan_native_scales()` 取代；spec/README 同步；GUI 标签「降采样」→「降采样方式」（最坏情况行宽 758px → MinWidth 750→780）。

## 验收

- **2x 模型要 4 倍 = 把模型跑两遍**：`--width 192`（48×32 输入）与手工"`-s 2` 跑两遍"的结果 **56 dB 级一致**（守卫测试 `test_target_above_native_uses_model_passes`）。
- **3 倍目标（原生 2x）**：与"4x 再缩小" **56.5 dB** 一致，与旧的"2x 再插值放大"只有 **33.5 dB** —— 确认走的是多轮模型 + 缩小（守卫测试 `test_target_between_scales_shrinks_the_model_result`）。
- **2.5 倍目标（原生 2/3）**：与"单轮 3x 再缩小" **55.3 dB** —— 确认计划优先单轮、不多跑（守卫测试 `test_target_between_native_scales_prefers_single_pass`）。
- **正好整数倍时收尾不缩放**：换 `--down-filter` 输出逐位相同（守卫测试 `test_exact_native_multiple_has_no_resize`）。
- 全量 pytest **81 passed**。

## 代价与已知边界

- 目标倍率越大轮数越多：耗时与内存按**累积尺寸**增长（如 2x 模型要 5 倍 = 3 轮 = 8 倍中间图）。spec 已写明。
- 模型只有 4x 档（rrdb / compact）而要 5 倍时，计划是 `[4,4]` = 16 倍再缩小 —— 这是"放大不用插值"的直接后果（waifu2x 同样只能按 2 的幂超冲）。
