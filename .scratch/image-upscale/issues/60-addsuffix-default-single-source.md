## 现状

「文件添加扩展名」的默认值是「开」这件事，在 `gui/MainWindow.xaml.cs` 里出现在多处：

- `_addSuffix = true` 字段初值（构造函数随后会用 `SettingsStore.Load()` 覆盖 → 初值实际不可达）
- `AddSuffixFromIndex(...)` 的兜底返回
- 灰置跟随里的 `isFile ? _addSuffix : true`（文件夹输入强制显示「开」）
- `SettingsStore.Load()` 缺键/非法值时的回退

命名方面：`_addSuffix` 读起来像动作而非状态；`AddSuffixFromIndex` 返回 bool 也是动词短语。

## 方案要点

- 把「默认开」收成**单一来源**（例如 `SettingsStore.DefaultAddSuffix = true`），上述各处引用它，
  让 `rg` 能一眼确认默认值只有一处定义（对齐仓库既有偏好：lessons §1.4「一个概念只允许一处真相」）。
- 命名（可选，判断项）：`_addSuffix` → `_suffixEnabled` 之类的状态式命名；若改，保持与
  `AddSuffixLabels` 表命名族的关系清晰。
