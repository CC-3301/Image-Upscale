## 维护者定案（2026-09-20）

- 下拉**第 4 项**「与输入格式相同」，**默认仍是 JPG**（不改现有默认行为）。
- 输入是 `1.jpeg` 时**保留输入的 `.jpeg`**（产物扩展名照抄输入的拼写，编码器把 jpeg 归一到 JPEG）。

## 方案要点

- 引擎 `-f same`（`RunOptions::format_same`）：输出格式从「整批一个值」改成**逐文件**——产物扩展名取该输入的扩展名原样（`get_file_extension`，大小写也保留），编码器由 `encoder_of_input_extension()` 归一（jpeg/jpg → jpg）；alpha 拍平到白底（JPG 路径）与编码分支都改用本文件的编码器。
- `NamingSegments` 去掉 `ext` 字段（整批一个扩展名的前提没了），改由 `single_file_outpath` 收一个 `file_ext` 参数；AUTO 的 `probe_denoise_level` 也改传本文件的编码器。
- 质量参数：界面在 `-f same` 时照样传 `-q`，落到 PNG 的那几个文件由引擎忽略（PNG 无损）。
- GUI：`SettingsStore` 加 `OutputFormatTokens/Labels`（`jpg/png/webp/same` ↔ `JPG/PNG/WebP/与输入格式相同`）+ `DefaultOutputFormatIndex` + 两个转换 helper；`FormatBox` 的项改由表填充（XAML 不再写死 `ComboBoxItem`），宽度 90 → 118px（容下 7 个中文字的标签）。
- setting.ini：`LastOutputExt` 的合法值集合加入 `same`。

## 未决 / 风险

- 「与输入格式相同」+ **单文件** + 关后缀段：`A.jpeg` 的产物就是 `A.jpeg` 本身（保留拼写）→ 命中原地覆盖（源图被替换）；这与 `-f jpg` 下的 `A.jpeg` → 新增 `A.jpg` 不同，属该选项的预期语义，已写进 `CONTEXT.md` / `README.md` / `spec.md`。
- 产物扩展名保留输入拼写意味着 `.PNG` 这类大写后缀会原样出现在产物名里；不做小写归一（字面口径，维护者选定）。
- 输出格式下拉宽度 90 → 118px：已核过「降噪与输出」栏行宽仍在可用宽内（见 Comments 的实测）。
