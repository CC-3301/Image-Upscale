## 维护者定案（2026-09-20 本轮 triage）

1. **开关只作用于文件输入**：目标是文件夹（递归批处理）时该开关**不生效**，永远按现有规则命名
   —— 输出到 `A-(模型名)-nN-<倍率|尺寸>/` 目录、内部结构原样镜像。
   （理由：目录模式去掉输出目录段会把产物写回源目录，二次运行会把产物当输入再放大一轮。）
2. 关闭时（文件输入）产物 = 源文件同目录 + **原文件名** + 输出格式扩展名；直通缩放的
   `-(Resize)-<尺寸>` 段同样不加。例：`B/A.png` + `-f jpg` → `B/A.jpg`。
3. **已存在文件的处理不变**：仍直接覆盖（spec 用户故事 18）。**不做**「跳过并记日志」，
   不引入 `--on-exists` 参数（原提案的跳过策略由维护者否决）。
4. **安全守卫**：关闭后缀且输出格式与输入相同（`A.png` + `-f png`）时目标路径就等于输入路径，
   必须**拒绝写盘**并报错，绝不覆盖源图。退出码走 IO 失败（3）。

## 方案要点

- 引擎新增布尔开关 `--no-rename`（`engine/src/engine_core.cpp`）：`print_usage` 文案 + 参数解析 +
  `single_file_outpath` 增一条分支（`in.parent_path() / (in.stem() + "." + ext)`）+ 目录模式忽略该开关。
- 守卫：生成 `outpath` 后比较 `weakly_canonical(outpath) == weakly_canonical(inpath)` → 命中即
  `fail(false, "refuse to overwrite input", outpath)` 并跳过该文件（不推理、不写盘）→ 退出码 3。
- GUI：新增「文件添加扩展名」下拉（`开` / `关`，位置与控件形态见工单 51），setting.ini 新增
  `LastAddSuffix`（默认 1 = 开，与现状一致）；仅当「输入是文件」且选择为「关」时传 `--no-rename`。
- GUI 日志映射：`refuse to overwrite input: ` 开头的 stderr 行 → 中文提示
  「✘ 拒绝覆盖输入文件（产物与输入同名，请把「文件添加扩展名」设为开）：<文件名>」。
