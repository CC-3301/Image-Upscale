## 报告（维护者 2026-09-18，v0.2.4 三张参考图）

`references/` 下三张图：`raw.jpg`（输入 1046×1500）与同参数（输出宽 1600、JPG 质量 90、默认降噪"无"）的两张产物。

- `raw-(realcugan-pro)-1600x.jpg`：整幅彩色噪声，内容只剩鬼影。
- `raw-(realcugan-se)-1600x.jpg`：结构尚在但整体发灰发白，黑线边缘出现黄色彩噪（"Three" 标题字最明显）。

## 复现（bld 引擎，工单书写时的构建）

```
image-upscale.exe -i raw.jpg -m realcugan-pro --width 1600 -f jpg -q 90   # 与参考图逐像素比对：一致
image-upscale.exe -i raw.jpg -m realcugan-se  --width 1600 -f jpg -q 90   # 同上
```

两张产物与维护者参考图一致（差异仅 JPEG 重编码），确认是当前构建的真实缺陷，不是陈旧二进制。

## 定位过程与证据

1. **模型文件无嫌疑**：`models/realcugan-pro|se/*` 与 nihui/realcugan-ncnn-vulkan 20220728 release 资产**逐字节相同**（md5 比对 8 个文件全 SAME）。
2. **引擎代码无自行改写**：`engine/src/realcugan.cpp` 与本项目注明的上游（同 release 的 master 源码）diff 仅 4 处适配——RGB/BGR 通道适配、`set_vulkan_device` 空指针适配、`_wfopen` 失败返回值、bicubic 指针空判；算法与分块结构完全一致。
3. **官方预编译二进制复现同样结果**：用 release 包内 `realcugan-ncnn-vulkan.exe` 跑同一张图，pro 输出与我们的产物同为彩色噪声（chroma>40 像素占比 0.735 vs 0.670），se 同样出现黄边彩噪。→ 不是本项目引入的回归。
4. **档位扫描锁定唯一变量**：上游 `-c syncgap-mode`（0 无同步 / 1 精确 / 2 粗略 / 3 极粗略，默认 3）扫描同一张全页图：

   | 模型（降噪"无"） | c0 | c1 | c2 | **c3（现状）** |
   |---|---|---|---|---|
   | realcugan-pro | 0.092 | 0.018 | **0.001** | **0.735**（崩） |
   | realcugan-se | 0.006 | 0.002 | **0.001** | **0.059**（黄边） |

   （数字为 chroma>40 的像素占比，越低越好；耗时 c3 1.50s / c2 1.56s / c1 1.92s）

5. **根因**：`engine_core.cpp` 的 `CuganEngine::configure` 把 `syncgap` 硬编码为 **3**。Real-CUGAN 的 SE 描述子是全图平均量，档位 3 用**固定的 32px 小图块**平均后全局复用（且只覆盖 3 的倍数个图块，尾部图块无人写入）；对 realcugan-pro/no-denoise 权重会把网络推出分布 → 整幅彩色噪声，对 realcugan-se/no-denoise 则留下线条边缘的黄边彩噪。档位 2 用与 `tilesize` 同尺寸的图块正确同步描述子。

## 修复

`engine/src/engine_core.cpp` 的 `CuganEngine::configure`：`impl.syncgap = 3` → `2`（含理由注释）。

- 同参数产物回归：pro / se 的 `--width 1600` 输出 chroma>40 占比从 0.67 / 0.039 降到 **0.000 / 0.000**；视觉上黑线为纯黑、标题字无彩边。
- 代价：全页 1046×1500 耗时 1.22s / 1.14s，相比档位 3 约 +5%。
- 未选档位 1（accurate sync）：实测全页彩噪反而高于档位 2（pro 0.018 vs 0.001），且耗时 +27%。

## 验收

- `tests/test_cugan_sync.py`：同步路径（tile 400 < 图宽 512）与单图块直通（tile 512）的产物差异不得灾难级。修复前 0.758 像素差 >100（红），修复后 < 0.25（绿）。该测试用确定性合成图，不依赖真实素材。
- `python -m pytest tests -q`：71 passed。

## 残留风险（已在工单 40 修掉）

`realcugan-pro` 在部分真实内容上仍崩成彩色噪声，当时判定为上游模型固有失稳。后查清是**引擎缺失官方 pro 系权重的 [0.15,0.85] 仿射归一化**（上游 issue #52），已由工单 40 修复并加回归测试；本工单的 `syncgap` 改动仍是有效修复（档位 3 对 pro 模型额外叠加了描述子平均的分布偏移，两者叠加才是工单 38 报告里那种整幅崩坏）。
