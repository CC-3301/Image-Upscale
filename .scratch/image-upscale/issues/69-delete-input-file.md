## 报告（维护者，2026-09-20）

添加一个选项「删除输入文件」（开/关）：打开后，模型输出时先删除输入文件，然后再输出文件。

## 维护者定案（2026-09-20）

- **时机改为「先写再删」**：产物写盘成功之后才删该输入文件。若输出名与输入名相同（原地覆盖，工单 58）则**不删**——那已经是同一个文件，删掉的就是刚写出的产物。理由：原话的「先删再写」在写盘失败（磁盘满/权限/崩溃）时会把源图与产物一起丢掉。
- 作用范围：**文件与文件夹输入都生效**，文件夹逐文件删（空目录不删）。
- 位置：与「添加扩展名」同一栏（工单 67 的「文件处理」）。
- 默认 **关**。

## 方案要点

- 引擎 `engine/src/engine_core.cpp`：
  - 新增 `--delete-input`（`RunOptions::delete_input`，usage 两行文案）。
  - `run_files`：**成功行之后**、`advance_progress()` 之前执行；产物与输入同路径时跳过（verbose 打 `input kept (output overwrites it): <path>`）；删除失败 → `log_err("cannot delete input: ...")` + `io_failures++`（退出码 3），继续处理后续文件、源图保持原样。
  - 路径比较 `path_equal_ci()`：两侧先 `weakly_canonical`，再用 `CompareStringOrdinal(..., TRUE)` 做大小写不敏感比较（lessons §3.13 口径；不用 `towlower`，其结果依赖进程 locale）；规范化失败退回逐字符比较，不把"比不了"当成"同一文件"。
- GUI：`DeleteInputBox`（项由 `SettingsStore.SwitchLabels` 填充）、`_deleteInput` 记忆值在构造函数读定（工单 59 口径）、`OnClosing` 无条件写回；开时向引擎追加 `--delete-input`。
- `setting.ini`：新增键 `LastDeleteInput`（1 = 开），非法值静默回退默认关。
