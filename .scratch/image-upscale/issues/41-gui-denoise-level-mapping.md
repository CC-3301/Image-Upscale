## 报告（维护者 2026-09-18，v0.2.5）

模型 `realcugan-pro`，降噪手动选「高」→ 任务无法开始，引擎报：

```
model realcugan-pro does not support denoise level 1
```

`realcugan-se`（自动/无/低/中/高 五档齐全）不受影响。

## 根源：下拉框序号被当成了档位

降噪下拉框按模型能力**动态增删项**（工单 23），而 `realcugan-pro` 的清单只有：

```
denoise none no-denoise
denoise high denoise3x
```

所以它的项是 `[自动, 无, 高]` —— **「高」落在序号 2**。构造命令行时却按序号推档位：

```csharp
if (dSel == 0) args.Add("auto");
else if (dSel == 1) args.Add("none");
else args.Add(dSel == 2 ? "low" : dSel == 3 ? "mid" : "high");
```

序号 2 → `low`（档位 1）→ 引擎拒绝。**只要模型缺 低/中 任一档，序号就不再等于档位**（缺 1 档时「高」错发成「低」，缺 2 档时错发成「中」）。

引擎侧行为是正确的，不应放宽：`--denoise high` 正常出 `-n3`，`--denoise low` 返回退出码 1 并报同一句错误。

## 修复

`gui/MainWindow.xaml.cs`：

1. 新增 `_denoiseLevels`：与下拉项一一对应的档位登记表（自动 = -1），填充项时同步登记。
2. 构造命令行时按登记值取名，不再用序号分支。
