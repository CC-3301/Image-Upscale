# 40: Real-CUGAN pro 系权重缺失官方仿射归一化（[0.15,0.85]）

**Parent:** .scratch/image-upscale/spec.md

**Category:** bug

**Status:** done（随 v0.2.5 发布：https://github.com/CC-3301/Image-Upscale/releases/tag/v0.2.5）

> *This was generated by AI during triage.*

## 来源

工单 38 的残留风险：`realcugan-pro` 在部分真实内容上整幅崩成彩色噪声，切任何 `syncgap` 档位都不消失，当时判定为「上游模型固有失稳」并另开本工单。

## 真正的根因（本工单查清）

官方 Real-CUGAN 对 **pro 系权重**（`weights_pro/*.pth`）在 pytorch 侧做了仿射归一化（`Real-CUGAN/upcunet_v3.py`）：

```python
self.pro = "pro" in weight                     # 权重里带 "pro" 键 = pro 系
def np2tensor(self, np_frame):
    if self.pro: ... .float() / (255/0.7) + 0.15     # [0,1] → [0.15,0.85]
    else:        ... .float() / 255
def forward(self, x, ..., pro):
    ...
    if pro: return ((x-0.15) * (255/0.7)).round().clamp_(0,255).byte()
    else:   return (x * 255).round().clamp_(0,255).byte()
```

**nihui 的 ncnn 移植没有这对变换**（上游 issue #52 "The implementation of pro model is inconsistent with the original repository"，2023-12 提出，至今 OPEN、无评论、无 PR）。本项目引擎照搬该移植，于是 pro 权重实际运行在训练分布之外。

为什么以前没被当成"引擎错"：网络近似仿射等变，两次变换近似相消 —— 普通内容上输出看不出差别（实测同一张图「输入归一化 + 输出反归一化」与「两者都不做」的差异 RMSE 约 7/255）。但输入落在 [0.15,0.85] 之外时 LeakyReLU/SE 不再可交换，高对比网点类内容会把激活推出量程 → 整幅彩色噪声。这也解释了工单 38 里"同一模型换个内容就崩"的现象。

## 定位证据（修复前，bld 引擎 + 官方预编译二进制）

1. 官方 `realcugan-ncnn-vulkan.exe`（同 release）对同一批 256×256 真实漫画切片复现同样的崩坏：`models-pro` 3/15 崩（chroma>40 占比 0.86 / 0.16 / 0.70），`models-se` 0/15。
2. 变体扫描：`up2x-no-denoise` 崩、`up2x-conservative` 部分崩、`up2x-denoise3x` 与 `up3x-no-denoise` 不崩、`models-nose` 不崩 —— 与权重是 pro 系/非 pro 系不完全对应，但与输入分布外程度相关。
3. **决定性验证**：把崩坏输入先按 `x*0.7+0.15` 预归一化再喂官方 exe（`models-pro`），崩坏消失：

   | 切片 | 原样输入 | 预归一化后 |
   |---|---|---|
   | 00 | 0.8587 | **0.0068** |
   | 09 | 0.1604 | **0.0284** |
   | 13 | 0.7049 | **0.0000** |

## 修复

1. `models/manifest.conf`：`realcugan-pro` 块新增 `pro yes`（清单是模型元数据的唯一真相，引擎与 GUI 共享；GUI 解析器按已知键取值，未知键忽略，无需改动）。
2. `engine/src/engine_core.cpp`：`ModelInfo` 增 `pro` 字段并解析 `pro`；`CuganEngine` 构造时写入 `impl.pro`（必须在 `load()` 建管线之前，故走构造函数而非 `configure()`）。
3. `engine/src/realcugan.h/.cpp`：新增 `bool pro` 与两个成员助手 `norm_in()` / `denorm_out()`，非 pro 时与旧行为逐位等价（`v*(1/255)` / `v*255`）；CPU 路径 16 处归一化点（8 输入 + 8 输出，alpha 项不动）改用助手。
4. 六个 shader（preproc / postproc / 4x_postproc × tta）新增 specialization 常量 `layout (constant_id = 1) const int pro = 0;`，归一化改成 `v * scale + bias`（pro → `0.7/255` +0.15，输出 → `255/0.7` −`0.15*255/0.7`），由 `load()` 在建管线时按 `pro` 传值。选 specialization 常量而非 push constant：SPIR-V 仍只需编译/缓存一份。
5. 4x postproc 的「残差 = 输入图」按同一仿射处理（与官方 `x_crop += interpolate(x00)` 后才反归一化一致）；当前没有 pro 4x 权重，非 pro 分支不变。

## 验收

- `tests/test_cugan_pro_norm.py`（新增）：256×256 合成高对比网点图（黑底稀疏白点），断言 `chroma>40` 像素占比 < 0.10；修复前 GPU 实测 **0.667**（红），修复后 **0.029**（绿）。固定 `-g 0`，无 Vulkan 设备时跳过（同一夹具下 cugan 的 CPU/GPU 后端结论不一致，成因未定且与本次修复无关，故不纳入断言）。
- `python -m pytest tests -q`：**74 passed**。
- 维护者场景回归（`references/raw.jpg` → `--width 1600`，JPG q90）：pro `chroma>40 = 0.0002`、se `0.0000`；耗时 pro 1.09s / se 1.26s。目视：黑线纯黑、标题字无彩边、网点结构保留。
- 非 pro 模型（waifu2x / realesrgan / realcugan-se）走恒等分支，输出与修复前逐位相同（scale=1/255、bias=0 与旧常量表达式等价）。
