# 45: AUTO 批量中「非零档在前、0 档在后」→ 沿用上一文件权重出图，命名却写 -n0

## 报告（全量代码审查，2026-09-18）

批量（目录输入）+ `--denoise auto` 时，如果**前一个文件解析出非零档、当前文件解析出 0 档**，当前文件会**继续使用前一个文件的权重变体**出图（例如 `denoise3x`），而输出文件名（`:805-817`）与 `configure`（`:846`）却按本文件档位写成 `-n0`。即：图被上一档位处理过，命名与日志说没有。

## 根源

1. 重载条件（改前 `engine_core.cpp:832`）：`s != loaded_scale || (denoise_auto && file_denoise != denoise_level)`。AUTO 下 `denoise_level` 恒为 0（`:1257`），所以当前文件解析为 0 时整条条件为假 → **不重载**。
2. 关键点：`impl.noise = denoise_level`（`:218` / `:233`）**不参与选权重**（只用于 `noise == -1 && scale == 1` 捷径，见 `waifu2x.cpp:167/540`、`realcugan.cpp:278/768`）；权重由 `resolve_model_files(..., file_denoise, ...)`（`:834` → `:600`）按档位选文件名。

## 触发范围

只有「非 0 档在前、0 档在后」这一种顺序会错；反序（0 在前、非 0 在后）会正确重载。单文件输入不触发。

## 测试为什么没抓到

`tests/test_auto.py:111-131` 的混合档用例把干净图 `a.png` 排在脏图 `b.jpg` **之前**，恰好避开触发顺序。

建议补一条内容级守卫：AUTO 目录中解析为 0 档的产物，应与同一输入用 `--denoise none` 单文件跑出的产物**逐位相同**（PSNR/差异断言比命名断言更能守住这类静默错配）。

## 回归守卫

`tests/test_auto.py::test_auto_batch_zero_level_after_dirty_reloads_none_weights`（脏图在前、干净图在后；逐位比对 `--denoise none` 单文件产物。内建顺序守卫：夹具必须保持「非 0 在前、0 在后」，否则用例会空转通过。红-绿已验证：改回旧代码后该用例失败）

## 已做（工作区，未构建未验证）

新增 `loaded_denoise`（`engine_core.cpp:666-670`），重载条件改为 `s != loaded_scale || file_denoise != loaded_denoise`（`:832`），加载成功后一并赋值（`:853`）。非 AUTO 场景下 `file_denoise == denoise_level` 恒定，行为不变。
