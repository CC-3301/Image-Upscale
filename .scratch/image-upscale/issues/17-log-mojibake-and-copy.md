# 17: 处理日志中文/日文乱码、不可复制、逐行不换行

**Parent:** .scratch/image-upscale/spec.md

**Category:** bug

**Status:** done（随 v0.2.1 发布：https://github.com/CC-3301/Image-Upscale/releases/tag/v0.2.1）

> *This was generated by AI during triage.*

## 报告（2026-09-14 人工测试）

处理日志输出有乱码，不支持中文、日文文件名；日志不能复制；每条日志是一行文本而不是一段文本（长行被截断）。

## Triage 验证记录（乱码根源已实证）

用中文文件名 `中文测试图.png` 实测引擎 `-v` 输出：stderr 字节为 `b'loaded bld/\xd6\xd0\xce\xc4\xb2\xe2\xca\xd4\xcd\xbc.png'` —— **引擎按 GBK 编码输出**（`fprintf("%ls")` 在重定向下经 C locale 转多字节，中文 Windows = GBK），而 GUI `EngineClient.Run` 设 `StandardOutputEncoding = Encoding.UTF8` 按 UTF-8 解码 → 乱码/解码失败。任何非 ASCII（中文、日文）路径必现。

修复分两侧：

- **引擎**：宽字符串显式转 UTF-8 再输出（`WideCharToMultiByte(CP_UTF8, ...)` 封装替换所有 `%ls` 输出点：stderr verbose 行、fail 行、路径相关报错）。注意 CLI 直接跑控制台场景的显示（控制台 CP 936 下 UTF-8 字节仍会乱，可 `SetConsoleOutputCP(CP_UTF8)` 或至少保证管道重定向正确——GUI 场景优先）。
- **GUI**：日志从 `ListBox`（单行、不可复制、不换行）换成只读 `TextBox`（`TextWrapping="Wrap"`、`IsReadOnly`、可框选 Ctrl+C）或 `RichTextBox`，追加日志用 `AppendText` 并自动滚动。

推荐 `ready-for-agent`。回归：中文/日文文件名的单文件与文件夹批处理，日志可读、可选可复制。
