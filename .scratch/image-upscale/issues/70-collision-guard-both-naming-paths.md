## 方案要点

- `engine/src/engine_core.cpp`：
  - 跑前守卫从 `if (no_rename)` 分支里提出来，**两条命名路径都跑**；产物路径按与 `run_files` 同口径的公式算（目录模式的降噪段只进目录名、不进文件名；`-f same` 时逐文件取输入扩展名）。
  - **逐文件档位（AUTO 档位不一致）时产物名在运行期才定**，跑前算不出来 → 那一路跳过跑前检查，改由 `run_files` 的**运行期守卫**兜：本轮已写出的产物路径集合（`canonical_path_key` + `OrdinalLess`，与工单 68/69 同一口径），命中别的输入序号即 `fail(false, "output path already written by another input", outpath)`（按 IO 失败计、退出码 3、源图不删）。

- 测试：`tests/test_naming.py` 新增 `test_folder_suffix_naming_rejects_colliding_outputs`（开后缀段 + `1.jpg` + `1.png` + `-f jpg` → 退出码 1、源图字节不变、不留输出目录；同目录配 `-f same` 则能跑完）；`tests/test_delete_input.py` 新增 `test_delete_input_matches_full_name_not_stem`（单文件 `1.jpg` + 同目录 `1.png` → 只删 `1.jpg`、`1.png` 字节不变）。

## 未决 / 风险

- 跑前守卫在「逐文件档位」那一路不生效（产物名运行期才定），靠运行期守卫兜 —— 后者是**中途**报错：此前已写出的产物会留在盘上（该文件计 IO 失败、源图不删）。已在 spec 写明。
