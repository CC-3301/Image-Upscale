# 39: 降噪档位在产物命名中一律写出（含 n0）

**Parent:** .scratch/image-upscale/spec.md

## 报告（维护者 2026-09-18，v0.2.4 人工测试）

> 如果选 AUTO 档位降噪，输出的文件夹从来没有 n0/1/2/3 的字眼，我都不知道它降没降噪

## 复现（修复前，bld 引擎）

| 场景 | 命名 |
|---|---|
| 单文件 + 手动"无" | 无 `n` 段 |
| 单文件 + 手动 低/中/高 | `-n1/2/3` |
| 单文件 + AUTO → 0 档 | **无 `n` 段**（与"没降噪"同名） |
| 单文件 + AUTO → 1/2/3 | `-n1/2/3` |
| 目录 + 手动 低/中/高 | 目录 `-n1/2/3` |
| 目录 + AUTO | **目录恒无 `n` 段**；内部文件名原样镜像 → 每个文件实际档位完全不可见 |

根因：`--denoise auto` 先把 `denoise_level` 置 0，再用它在文件循环**之前**拼 `denoise_seg`，所以目录名永远拿不到档位；单文件路径只在 `file_denoise > 0` 时才补 `-nN`，0 档被吞掉。`tests/test_auto.py` 里的 `test_auto_folder_naming_uses_first_file_level` 名字声称目录名用首文件档位，实际实现从未如此（首文件恰好为 0 档才"碰巧"通过）——本工单把它变成真的。

## 维护者决策（2026-09-18，问答定案，含后续修订）

1. **降噪段一律写实际生效档位**：手动"无"与 AUTO 解析为 0 都写 `-n0`；低/中/高写 `-n1/2/3`。手动/自动口径一致。
2. **目录模式**（后续修订）：AUTO 逐文件解析；
   - 全批档位**一致** → 目录名写该档位（如 `-n1-`），内部文件名原样镜像；
   - 档位**不一致** → 目录名写 `-nX-`，每个产物文件名各补自己的 `-nN`（如 `1-n0.png`、`2-n2.png`），内部子目录结构仍原样镜像。
   - 手动档天然全批一致 → 目录名 `-nN-`，内部名不变。
3. **日志区不加行**：不新增中文解析提示，靠命名体现。
4. 直通缩放仍写 `A-(Resize)-<尺寸>`，永不带降噪段（不跑模型就没有降噪档位）。

## 实现

`engine/src/engine_core.cpp`：

- 新增 `probe_denoise_level(path, format)`：估计档位用，解码后处理（灰度转 RGB、RGBA 分 jpg/非 jpg 两路）与 `run_files` 主循环逐字对齐，保证探测结果与实际推理用的是同一档位；解码/内存失败返回 0（等同"无降噪"）。
- 目录分支改为**先递归收集 → 逐文件探测 → 再建目录**：`found.empty()` 时直接报 "no matching image files"（原来的后置空判成为死代码，已删）。探测成本为建目录前多一遍全量解码（每文件只留单帧内存，开完即释）；推理仍占绝对大头。
- 目录 + AUTO：全部探测档位相同 → 目录 `-nN`；不同 → 目录 `-nX` 且 `denoise_per_file = true`。
- `output_files` 改为存**不带扩展名的基名**，扩展名与降噪段在 `run_files` 逐文件拼（`denoise_per_file` 时补 `-nN`，否则不补），使镜像语义与混合语义共用一条路径构造。
- `denoise_seg` 恒为 `-nN`；AUTO 单文件名恒用解析档位。
- 首文件不可解码时退回 0；混合判定中任何探测失败都计为 0。
