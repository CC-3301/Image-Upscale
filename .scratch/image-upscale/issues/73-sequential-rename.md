# 73: 序列化重命名

**What to build:** 「文件处理」栏新增开关（默认关）。开启后产物按现有文件名的自然顺序编号为 `001`、`002`、`003`……，源文件名全程不变；编号与「添加后缀」四态叠加使用。产物写盘改为「临时文件 → 删源 → 改名」，保证源名与目标名相同时不会出现「改名覆盖源、随后又被删源清掉」。

**Blocked by:** 74（产物命名要按四态拆分落地）。

**Status:** ready-for-agent

- [ ] 文件夹输入 `2.jpg 1.jpg 3.jpg` → 产物按 `1 / 2 / 3` 的顺序编号为 `001`、`002`、`003`
- [ ] 排序口径与 Windows 资源管理器一致：数字按大小（`2.jpg` 在 `10.jpg` 前）、字母不分大小写、中文按拼音
- [ ] 3 位补零；文件数超过 999 时自然变 4 位
- [ ] 每个子文件夹各自从 001 起，子文件夹本身不改名
- [ ] 单文件输入 → 产物编号为 `001`
- [ ] 只有 jpg/jpeg/png/webp 参与排序与编号，其它文件不动
- [ ] 「删除输入文件」关闭时，跑完的源文件名与跑前完全一致
- [ ] 与「添加后缀」四态叠加后的产物目录与产物名符合 74 的表
- [ ] 引擎提供 `--sequence`，`--help` 有说明
- [ ] GUI 开关可记忆到 `setting.ini`，缺键或非法值回退「关」
- [ ] 开关关闭时行为与改动前完全一致
- [ ] 每个文件处理完就地收尾：产物写 `<目标名>.iu-tmp` → 删源（「删除输入文件」打开时）→ 改名为目标名
- [ ] 临时后缀是 `.iu-tmp`，输入扫描不识别，残留不会被当成图片
- [ ] 先删后改：源名与目标名相同时，不会出现"改名覆盖源、随后又被删源清掉"的窗口
- [ ] 编码或写盘失败时删掉自己的 `.iu-tmp`；改名失败时保留 `.iu-tmp` 并把路径写进日志，该文件按 IO 失败计
- [ ] 崩溃残留的 `.iu-tmp` 不自动清理；再次处理同一目标时同名覆盖
- [ ] 撞车拦截只保留"两个开关都关"时的既有报错；序列化重命名或删除输入文件任一打开时一律覆盖
- [ ] 「序列化重命名」与「删除输入文件」都关时，跑前撞车报错仍然生效（退出码 1，不写出任何产物）
- [ ] 上述两个开关任一打开时，同样的输入一律覆盖，不再报错
