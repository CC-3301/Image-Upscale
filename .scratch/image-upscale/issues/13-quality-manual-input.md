## 报告（2026-09-14 人工测试）

输出质量只能用滑条设置，不能手动输入精确数值。

## Triage 验证记录（代码确认）

`gui/MainWindow.xaml` 质量仅 `Slider`（0-100，步进 1）+ 只读数值 `TextBlock`；无输入途径。选 37 这类精确值要拖很多次。

## 分诊建议

推荐 `ready-for-agent`（trivial）：滑条旁加一个小 `TextBox`（宽 ~48），与 `QualitySlider.Value` 双向同步，输入超界（<0 / >100 / 非数字）时回退当前值或钳制到 0-100。

## Comments

### Agent Brief（2026-09-14 推进 ready-for-agent）

**Category:** enhancement
**Summary:** 输出质量支持手动输入精确数值，与滑条双向同步

**Current behavior:**
输出质量仅能通过滑条（0-100，步进 1）设置，输入精确值（如 37）困难。

**Desired behavior:**
滑条旁提供小输入框：输入即时反映到滑条，拖动滑条同步回输入框；非法输入（非数字、越界）被钳制或回退，不产生非法参数。

**Acceptance criteria:**
- [ ] 输入 37 → 滑条同步到 37，开始处理后引擎收到 `-q 37`
- [ ] 输入 -5 / 150 / abc → 钳制或回退到合法值，不崩溃、不发送非法参数
- [ ] 滑条拖动 → 输入框同步
- [ ] PNG 格式下质量输入仍不发送 `-q`（与现有行为一致）

**Out of scope:**
- 其他数值控件的输入方式调整
- 质量预设（高/中/低快捷档）

### 实施记录（2026-09-14）
- 质量输入框与滑条双向同步；非法输入失焦回退；引擎参数始终取滑条值
- 人工：输入 37 同步；输入 abc/150 失焦回退
