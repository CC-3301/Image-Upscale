# 46: 模型加载失败被吞：load_param/load_model 返回值未检查 → 引擎报「成功」

**Parent:** .scratch/image-upscale/spec.md

**Category:** bug

**Status:** done（随 v0.2.6 发布：https://github.com/CC-3301/Image-Upscale/releases/tag/v0.2.6）

> *This was generated by AI during triage.*

## 报告（全量代码审查，2026-09-18）

三个引擎实现在加载权重时**丢弃** `net.load_param()` / `net.load_model()` 的返回值：

- 改前 `engine/src/waifu2x.cpp:74,86,91,92`
- 改前 `engine/src/realesrgan.cpp:77,89,94,95`
- 改前 `engine/src/realcugan.cpp:133,145,152-153`

ncnn 的接口契约是「return 0 if success」（`engine/third_party/ncnn/src/net.h:69-92`），失败返回非 0（例如 `.param` 魔数不是 `7767517` 时，`net.cpp:1317/1692` 会判失败）。

**后果**：权重文件缺失、被截断、或被替换成非 ncnn 内容时，`load()` 仍返回成功 → `engine_core.cpp` 判不出 → **退出码 0、界面显示「完成」**，用户拿到坏图却以为一切正常。这也违反 `docs/lessons.md` §1.5「退出码是两侧共同契约」（GUI 期待模型失败为 2）。

## 已做（工作区，未构建未验证）

1. 三个 `load()` 都检查两个返回值，非 0 即 `return -1`（含 `#else` 非 Windows 分支）。
2. `engine_core.cpp` 加载失败分支额外打印**出问题的那份模型文件路径**：`model files: <path>`（经 `utf8_from_wide` 走回调，符合 lessons §1.3 的输出编码约定）。

失败时走既有的 `fail(true, ...)` → `infer_failures` → **退出码 2**（`engine_core.cpp:1025-1029`）。

## 仍未做（候选，需先确认再动）

| 层次 | 坏法 | 能否静态检测 |
| --- | --- | --- |
| 1 | 文件不存在 / 打不开 / 大小为 0 | ✅ 已覆盖（`_wfopen` 失败 + load 返回值） |
| 2 | 内容不是 ncnn 模型（被替换） | ⚠️ 现由 ncnn 内部魔数校验兜住；可考虑加载前自查首行 `7767517` |
| 3 | `.param` 可读但 `.bin` 缺失/截断 | ✅ 已覆盖（`load_model` 返回非 0） |
| 4 | 文件完整但权重数值被损坏 | ❌ 只能靠输出异常间接发现（整幅彩噪/全黑） |
| 5 | param 与 bin 来自不同版本 | ⚠️ 多数表现为层数/形状不符 → 归入第 3 层 |

候选加固：加载前校验 `.param` 首行魔数与两文件非空；让 `process()` 的 `extract` 失败上报（Real-CUGAN 各变体目前无条件 `return 0`，`waifu2x.cpp:540` 之后同理）；发布时记录模型文件大小/哈希。

## 实测证据（2026-09-18 红-绿验证）

把三处修复临时改回旧代码、重新编译后跑新增回归测试，`bin-truncated` 用例得到的返回码是 **3221225477（0xC0000005，访问违例）**：坏权重在旧代码下**不是静默成功，而是直接崩进程**。stderr 里 ncnn 自己已经报了：

```
ModelBin read float16_weights failed 88
layer load_model 2 conv2_layer failed
```

修复后同一用例返回 **2（EXIT_INFER）**，并输出 `model load failed` 与出问题的那份模型文件路径。
