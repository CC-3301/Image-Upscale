# 11: 输入栏只读且不响应拖拽

**Parent:** .scratch/image-upscale/spec.md

**Category:** bug

**Status:** ready-for-agent

> *This was generated by AI during triage.*

## 报告（2026-09-14 人工测试）

输入栏是死的，不能互动：不能更改已设置的文件路径，拖文件到输入栏无效；但拖到输入栏以外的任意 UI 区域却可以输入。

## Triage 验证记录（代码确认）

`gui/MainWindow.xaml` 输入栏 `TextBox` 声明了 `IsReadOnly="True"` → 无法编辑路径（浏览选错后只能重新浏览）。

拖拽不一致：`AllowDrop` 挂在 `Window` 上，但 WPF `TextBox` 默认处理拖拽事件不冒泡 → 光标落在输入框上时 `OnDrop` 不触发；落在其余区域才命中窗口级 `OnDrop`。与 GroupBox 标题"输入（支持拖入文件或文件夹）"的承诺相悖。

## 分诊建议

推荐 `ready-for-agent`。修复方向（二选一或组合，需维护者定夺）：

- 允许编辑：去掉 `IsReadOnly`，开始处理时校验路径存在性（现有校验已覆盖）
- 拖拽：给 `TextBox` 挂 `PreviewDragOver`/`PreviewDrop`（隧道事件先于 TextBox 内建处理）或 `AllowDrop` + 事件处理

### Agent Brief（2026-09-14 推进 ready-for-agent）

**Category:** bug
**Summary:** 输入框只读且拖拽在其上无效，交互与"支持拖入"的界面承诺不一致

**Current behavior:**
输入路径框为只读，浏览选错后无法手改；文件拖到输入框上无响应（文本控件拦截了拖拽事件），拖到窗口其余区域才生效。

**Desired behavior:**
输入框可编辑；拖放文件/文件夹到输入框与拖到窗口其他区域行为完全一致。路径有效性校验仍发生在"开始处理"时。

**Acceptance criteria:**
- [ ] 浏览选择路径后可用键盘修改输入框内容
- [ ] 拖文件到输入框上，输入框内容更新（与拖到窗口其他区域一致）
- [ ] 无效路径（手动输入不存在路径）在开始处理时仍被拦截并提示
- [ ] 手动验收：浏览→修改→处理、拖拽→处理 两条链路通过

**Out of scope:**
- 多文件/多文件夹同时拖入的合并选择（维持现有取第一个的行为）
- 最近输入历史下拉
