# Image-Upscale —— 图像超分工具

> 术语遵循根目录 `CONTEXT.md`；推理栈决策见 `docs/adr/0001-ncnn-vulkan-inference-engine.md`。
> 行为参照物：waifu2x-caffe（已停更，RTX 50 系无法运行）。

## Problem Statement

用户手上有大量低分辨率/有压缩伪影的图片（漫画、插画、照片等），想获得清晰的高分辨率版本。现有的主力工具 waifu2x-caffe 已停更 6 年，绑死旧版 Caffe/CUDA，在 RTX 50 系等新显卡上无法运行；它自带的模型也已过时，而现代替代品（如 Real-ESRGAN）会过度涂抹、破坏原有设计（如线稿边缘与网点结构）。

## Solution

一个解压即用的 Windows 工具（单一 GUI，引擎进程内融合，无 CLI），推理引擎基于 ncnn + Vulkan，不绑死 CUDA 版本，Nvidia/AMD/Intel 显卡通用并有 CPU 兜底。内置按图像类型分组的现代模型（漫画、插画、照片、通用，以保线稿、保网点、拒绝过度涂抹为选型标准），支持从 waifu2x-caffe 延续下来的核心使用习惯：倍率模式、目标尺寸模式（宽/高二选一）、直通缩放、递归批处理（仅顶层重命名）、降噪档位（含 AUTO）与输出格式/质量控制。

## User Stories

1. 作为用户，我想把图片超分到所选模型的原生倍率，以便在大屏幕上清晰阅读线稿、网点和细节。
2. 作为用户，我想让工具默认使用保线稿、保网点的模型，以便结果不被过度涂抹破坏原有设计。
3. 作为用户，我想在打包模型中按图像类型选择（漫画/插画/照片/通用），以便不同来源的图片都得到合适处理。
4. 作为用户，我想把自定义 ncnn 模型放入 models 目录即可使用，以便尝试 OpenModelDB 上的新模型（如 MangaScaleV3，其许可禁止我们代为分发）。
5. 作为用户，我想把整个文件夹 A（内部嵌套 B、C 多层）拖进 GUI 一次处理，以便整本漫画一键超分。
6. 作为用户，我希望递归处理时只有顶层文件夹 A 被重命名为 `A-(模型名)-[nN-]<倍率或尺寸>`，内部 B/C 目录与图片文件名原样镜像，以便与 waifu2x-caffe 行为一致、方便对照原图。
7. 作为用户，我想使用目标尺寸模式：只指定目标宽或目标高（二者不能同时指定），另一边等比推算，以便图片精确适配我的设备屏幕。
8. 作为用户，当指定目标尺寸小于原图时，我希望跳过模型推理、直通缩放（等比、不裁掉画面）直达目标，以便秒级完成而不用等推理。
9. 作为用户，我希望直通缩放产物的输出名中模型位置写 `Resize`（如 `A-(Resize)-1920x`），以便一眼区分哪些图没经过推理。
10. 作为用户，我想选择输出格式 JPG（默认）/ PNG / WebP，且输出格式不跟随输入格式，以便统一管理产物。
11. 作为用户，我想调整 JPG/WebP 输出质量 0-100，以便在体积与画质间权衡。
12. 作为用户，我想选择降噪档位 AUTO / 无 / 低 / 中 / 高，以便处理有 JPEG 伪影的扫描图或保留原有质感的干净图。
13. 作为用户，我希望 AUTO 档自动检测伪影强度并映射到当前模型的档位，以便不用逐张猜测降噪力度。
14. 作为用户，当选中的模型不支持降噪（如 digital-art-4x、导入的自定义模型）时，我希望降噪选项被禁用并提示，以免误以为降噪生效。
15. 作为用户，我想处理带透明通道（alpha）的 PNG，输出 PNG/WebP 时透明被保留且同步超分，以便处理漫画素材和贴纸。
16. 作为用户，当 alpha 图以 JPG 输出时，我希望透明区域与白色背景合成，以便漫画场景下产物不出现黑底。
17. 作为用户，我想输入 .jpg / .jpeg / .png / .webp 后缀的静态图片，以便覆盖常见来源（waifu2x-caffe 的 `jpg:jpeg:webp:png` 同款匹配）。
18. 作为用户，当输出文件与已有文件同名时，我希望直接覆盖，以便重复运行即重新生成。
19. 作为脚本用户，我想用命令行参数完成与 GUI 完全相同的所有功能，以便写脚本批量处理。（已被 ADR-0002 取代：v0.2.2 起 CLI 不再随发布分发；参数面保留为测试缝）
20. 作为脚本用户，我想用退出码区分成功与失败（参数错误/推理失败/IO 错误不同码），以便脚本可靠地判断结果。（退出码语义保留：DLL 返回值与测试缝薄壳共用）
21. 作为用户，我想在处理大图时由引擎自动选择 tile 分块，以便不爆显存；也可以手动调小以便低配机器运行。
22. 作为用户，当机器没有可用 Vulkan 设备时，我希望自动回退 CPU 推理，以便工具永远可用（只是慢）。
23. 作为用户，我想在 GUI 中看到批处理进度与逐文件成功/失败汇总，以便确认全部处理完成。
24. 作为用户，我想下载一个 zip 解压即用，免安装、不联网，以便在任何 Windows 机器上立即可用。
25. 作为用户，我想让 GUI 全程只有中文，以便无障碍使用。
26. 作为用户，我想用倍率模式（如 2.0x）永远放大图片，以便原图很小时也能批量放大。
27. 作为脚本用户，我想在参数互斥（倍率/宽/高同时指定）时得到明确的报错信息，以便快速修正脚本。（随 19 不再对终端用户暴露，引擎内保留）
28. 作为用户，我希望超分在目标尺寸模式下**放大方向全部由模型完成（不做插值放大）**，且收尾只做缩小，以便超分质量对齐 waifu2x（工单 43 修定；原为“只做一次原生推理再精确 resize”）。

## Implementation Decisions

- **架构（ADR-0001/0002）**：推理引擎为 C++ 静态逻辑（内置 ncnn，Vulkan 后端 + CPU 后端），编译为 iu_engine.dll，GUI（C# WPF）经 P/Invoke 进程内调用（导出 iu_run）；另构建 CLI 薄壳 exe 仅作测试缝，不随发布分发；GUI 不承担推理职责。
- **AUTO 收进引擎**：伪影启发式估计器位于引擎内，CLI 接受降噪参数 `auto`；估计器只输出规范档位（无/低/中/高），规范档位经各模型的元数据映射表转换为其专属参数（如 waifu2x 系 noise 0-3、Real-CUGAN no-denoise/denoise1x-3x、realesr-general-x4v3 的 0-1 连续强度取 0/0.33/0.66/1.0）。AUTO 要求该模型 无/低/中/高 **四档齐备**（否则报参数错误、退出码 1）；档位不连续的模型（如 `realcugan-pro` 只有 无/高）在 GUI 中不提供「自动」项（工单 44）。
- **模型元数据清单**：每个模型声明显示名、架构、原生倍率列表、降噪映射（或不支持）、图像类型分组；GUI 与引擎共享该清单。不支持降噪的模型（digital-art-4x、默认的导入模型）在 UI 中禁用降噪选项。导入模型 = 放入 models 目录、出现在模型列表中，默认不支持降噪。
- **打包模型清单**（许可已核实）：
  | 分组 | 模型 | 原生倍率 | 降噪 |
  |---|---|---|---|
  | 漫画 | `waifu2x_upconv_7_art`（原 waifu2x-caffe“2D插图-UpRGB”，工单 30 改名） | 2x | 无/低/中/高 |
  | 漫画 | `waifu2x_cunet`（原“CUNet”，工单 30 改名） | 2x | 无/低/中/高 |
  | 漫画 | `realcugan-pro` | 2x/3x | 无/高（档位不连续 → 不提供 AUTO，工单 44） |
  | 漫画 | `realcugan-se` | 2x/3x/4x | 无/低/中/高（保守档 -1 不暴露） |
  | 插画 | `digital-art-4x`（模型名沿用 Upscayl 原名） | 4x | 不支持 |
  | 照片 | `waifu2x_upconv_7_photo`（工单 30 改名） | 2x | 无/低/中/高 |
  | 通用 | `realesr-general-x4v3` | 4x | 连续 0-1，按映射表取档 |
- **尺寸模式（三选一互斥）**：`--scale` 倍率 / `--width` 目标宽 / `--height` 目标高。倍率模式永远超分（单轮原生倍率）；目标尺寸模式下目标 ≥ 原图 → **多轮原生超分**：按原生档反复跑模型直到累积倍率 ≥ 目标（在“轮数最少”的方案里取“累积倍率最小”的档位组合：存在单档 ≥ 目标倍率就用那一档；超过模型最大原生档时逐轮叠加，如 2x 模型要 3 倍 → 2x 再 2x = 4x），再把结果**缩小**到精确目标 —— **放大方向一律由模型完成，不做插值放大**（对齐 waifu2x 的循环放大 + 收尾缩小，工单 43）；目标 < 原图 → 直通缩放（跳过推理，高质量重采样，不裁画面，保持宽高比适配指定维度）。代价：目标倍率越大轮数越多，耗时与内存按累积尺寸增长。
- **降采样方式（工单 42）**：`--down-filter lanczos（默认）/catmullrom/bicubic/box`；**只用于缩小**：目标尺寸模式的收尾缩放（把多轮模型结果缩到精确目标）、直通缩放、以及它们的 alpha 缩放。放大已由模型多轮完成（工单 43），不再有插值放大；`resize_rgb` 里非缩小的分支只是四舍五入导致目标比模型输出多 1 像素时的保底。倍率模式不涉及缩放，该参数无效果。该选择**不入输出文件名**（同图换滤镜重跑会覆盖同名产物，验收对比时需自行改名）。命名口径：界面 Bicubic 的核是 Mitchell-Netravali，界面 Catmull-Rom 的核是 Catmull-Rom，Box = 面积平均。
- **输出命名规则**（仅顶层重命名，内部目录/文件名原样镜像；输入单文件时产物落在同目录；模型名段用括号包裹，因其常含连字符）：
  | 模式 | 顶层命名示例 |
  |---|---|
  | 倍率模式（无降噪） | `A-(digital-art-4x)-n0-2.0x` |
  | 倍率模式 + 降噪中 | `A-(digital-art-4x)-n2-2.0x` |
  | 目标尺寸（宽 1920） | `A-(cunet)-n0-1920x` |
  | 目标尺寸（高 1080）+ 降噪低 | `A-(cunet)-n1-1080x` |
  | 目录 + 自动，全批同档 | `A-(cunet)-n1-2.0x/`（内部名原样镜像） |
  | 目录 + 自动，档位不一致 | `A-(cunet)-nX-2.0x/`，内部 `1-n0.png`、`2-n2.png` |
  | 直通缩放 | `A-(Resize)-1920x`（无降噪段） |

  降噪段规则（工单 39 修定）：一律写实际生效档位 `n0/n1/n2/n3`（低/中/高 = 1/2/3，无降噪 = 0），插在模型名段之后、倍率/尺寸段之前；AUTO 写该文件解析后的实际档位（不写 auto）。AUTO + 目录模式：全批档位一致时目录名写该档位、内部文件名原样镜像；档位不一致时目录名写 `nX`，每个产物文件名各补自己的 `-nN`（内部目录结构仍原样镜像）。直通缩放不跑模型，永远无该段。
- **输出格式**：JPG（默认）/ PNG / WebP，不跟随输入格式；质量参数 0-100 默认 90，作用于 JPG 与 WebP（WebP 有损档），PNG 无损忽略该参数。
- **alpha 处理**：PNG/WebP 输出 → RGB 与 alpha 分离推理后合成（工单 43 起 alpha 与 RGB 走同一条模型放大链，收尾同样只做缩小，避免插值放大在透明边缘留光晕）；JPG 输出 → 与白色背景合成。
- **输入**：按扩展名匹配 `.jpg` `.jpeg` `.png` `.webp`；递归遍历文件夹。
- **冲突策略**：输出与已有文件同名时直接覆盖。
- **引擎行协议契约（工单 27 后为 DLL 回调与薄壳 exe 共用）**：行式进度输出（GUI 解析显示）、语义化退出码（0 成功；参数错误/推理失败/IO 错误各异）、`--tile`（0=auto）、`--gpu-id`（-1=CPU，默认自动，供排障用，GUI 不暴露）。
- **GUI**：拖拽或选择文件/文件夹、模型选择（A-Z 平铺，工单 21；原“分组显示”）、降噪档位（随模型能力禁用；档位不连续时不提供“自动”，工单 44）、尺寸模式单选（倍率/宽/高）、降采样方式（Lanczos/Catmull-Rom/Bicubic/Box，默认 Lanczos，与降噪和输出同行，写在输出质量之后）、格式与质量、进度与汇总列表；仅中文。
- **分发**：portable zip（引擎 exe + 模型目录 + GUI exe）；代码许可 MIT。

## Testing Decisions

- **测试缝（工单 27 后两条）**：① 引擎 CLI 薄壳进程边界（行为回归，字节级兼容历史）；② iu_engine.dll 导出面（ctypes 直调 iu_run，锁 P/Invoke 契约）。所有自动化测试断言文件系统产物；引擎内部组件不开测试缝，GUI 无自动化测试（手动验收）。
- **好测试的标准**：只断言外部可见行为（产物路径与命名、图片尺寸、格式、质量元数据、退出码、stderr 报错文案），不断言内部实现（tile 策略、估计器算法、ncnn 调用方式）。
- **确定性断言**：命名规则全表、递归镜像（A/B/C 结构）、直通缩放触发条件与尺寸、格式与质量、覆盖行为、三选一互斥报错、扩展名匹配、退出码。
- **推理断言**：64px 级小图 + 固定 CPU 后端，断言输出尺寸/可解码性 + PSNR 容差阈值；不做逐像素对比（Vulkan 数值不确定性）。
- **先例**：绿地项目无既有测试；nihui 系 CLI 工具（waifu2x-ncnn-vulkan / realcugan-ncnn-vulkan）的行为语义作为参照。

## Out of Scope

- 动图（GIF/APNG）与视频超分。
- DAT/SwinIR 等 transformer 架构模型支持（含 2x-Manga-Ora）；双推理引擎（ONNX Runtime/DirectML）。
- 模型训练/微调。
- GUI 多语言（仅中文）；before/after 对比预览（记入 2.0 backlog）。
- 安装包（MSI/NSIS）；自定义输出目录参数（输出位置由命名规则唯一决定）。
- 多 GPU 选择 UI（引擎保留 `--gpu-id` 参数即可）。
- TTA（test-time augmentation）UI 暴露。
- 打包许可不允许再分发的模型（MangaScaleV3 等由用户经导入功能自取）。

## Further Notes

- Real-CUGAN 的"保守档"（-1）与 1x 纯降噪模式不在 UI/CLI 暴露，属模型映射表内部的自由度。
- 倍率显示统一 `2.0x` 格式；目标尺寸只写用户指定的那一维度（`1920x` / `1080x`）；降噪段恒为 `n0/n1/n2/n3`（无降噪 = 0，低/中/高 = 1/2/3），AUTO + 目录且全批档位不一致时目录段为 `nX`，模型名段以括号包裹。
- 目标尺寸 ≥ 原图时的原生倍率选择策略：取"原生倍率 ≥ 目标/原图"的最小档，不足时用最大档超分再上采样 resize。
- 后续版本候选（backlog，不承诺）：before/after 预览、多语言、安装包、transformer 模型双引擎。
